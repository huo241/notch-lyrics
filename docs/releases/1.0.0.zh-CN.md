# Notch Lyrics 1.0

**这不是一次补丁更新。** 1.0 是第一个「Notch Lyrics 自己拥有身份、拥有歌词链路、
拥有更新通道」的版本。

那个刘海你会认得——但刘海底下几乎没有一样东西还是原来的。

---

## 自己的身份

凡是用户或贡献者能碰到的地方，现在都是本项目自己的名字：

| 原来 | 现在 |
| --- | --- |
| 工程 / target / scheme 叫 `boringNotch` | `NotchLyrics` |
| Bundle ID `theboringteam.boringnotch` | `blog.snappy.notchlyrics` |
| XPC 助手 `BoringNotchXPCHelper` | `NotchLyricsXPCHelper` |
| 沿用的图标 | 全新图标——黑暗刘海缝里漏出的一道暖光 |

GPL 要求修改版必须声明自己是修改版，这一点做到了：`NOTICE` 文件、三份 README 顶部的
修改声明（起始日期 2026-10-06）、以及「关于」面板里的一行说明。

## 歌词：从查询这一层重建

旧的查法是「问 LRCLIB 一个问题，答不上来就算了」。**绝大多数抓不到歌词的歌，其实库里都有**
——是问法错了。三处改动解决了这个问题。

**一、不再要求时长分毫不差。** LRCLIB 的精确匹配接口，对时长的容差只有**两秒**。一首上报
时长差三秒的歌（重发版、淡出版、修过母带的版本）在那条路径上等于不存在。现在改成逐级下降：
带时长查 → 不带时长查一遍同样的查询 → 再退到搜索接口、结果本地打分。

**二、把标题里的噪音剥掉。** 候选按播放器上报的原样派生，顺序是：原拼写 → 去掉括号后缀
（`(Live)`、`(Remastered)`）→ 去掉破折号尾巴（`- Remastered 2011`）→ 只留第一位艺人。
**原拼写永远排第一**，所以干净的曲目完全不受影响。

**三、先打分，再采信。** 搜索结果会跟正在播放的曲目比对——标题、艺人、时长，加权计算——
分数不达标的直接丢掉，而不是显示出来。**匹配错歌比什么都不显示更糟。**

顺带修掉一个真 bug：查询串的编码用的是 `urlQueryAllowed`，而这个字符集**不会**转义
`&`、`=`、`+`。任何标题里带 `&` 的歌，请求都在那个字符处被截断。

**当前歌词行会跟着播放进度填充。** 没有跳字球，没有逐字高亮——当前行从暗色向亮色擦过去，
用它自己的时长作分母，并且**以文字自身实测宽度为基准**（不是面板宽度），所以短句和长句在
屏幕上填满的速度是一样的。

*没有做的：逐字卡拉OK。* LRCLIB 的格式原生支持，接口也确实返回了那个字段，代码本可以写——
但我实测扫描了约 **973 条**真实记录，带**真实词级时间戳**的是 **0 条**。
一个永远不会亮的功能，不值得发。

## 便签：备忘录，或者 Obsidian

便签面板现在会问你这条便签存到哪——原来的「备忘录」，或者 Obsidian 某个库里的文件夹。
选库是一次性的系统授权弹窗，授权以 security-scoped bookmark 保存，**没有新增任何 entitlement**。
只有目标是「备忘录」时才会去拉文件夹列表，把那次 Apple Events 往返从常走路径上挪开。

## 更新通道换成本项目自己的

现在 Sparkle 查的是本仓库的更新源、验的是为本项目生成的密钥，
`scripts/release.sh` 一条命令完成构建、打包、签名、写入 appcast。

## YouTube Music 报上自己的名字

跟它打交道的那个 YouTube Music 桌面客户端，是按客户端名字维护授权名单的，而这个 app 一直
顶着一个从来不属于自己的名字。现在它自称 `notchLyrics`——副作用是桌面端会再弹一次允许框，
点一次即可。

## 修复

- 歌词开关的文案是 *"Show lyrics below artist name"*——「艺术家名下方」这个位置早就没有了。
  歌词在**打开刘海后右侧的独立面板**里，和日历、摄像头轮流占位。现在文案是
  **「在刘海显示歌词」**，中文语言包也从「漏英文的占位」换成了真正的翻译。

## 已知限制

- **这个构建没有 Apple 开发者证书签名。** 它是 adhoc 签名 + Sparkle 的 EdDSA 签名验证。
  首次打开时 macOS 会拦下来，需要**右键 → 打开**并在弹窗里再确认一次。想免除这一步，
  需要付费开发者账号。
- **自动更新要等 `updater/appcast.xml` 推到 `main`、并且同时发布安装包之后才真正生效。**
  在那之前更新源是**故意留空的**，免得有人被推到一个还不存在的下载地址。
- **歌词受 LRCLIB 的收录范围限制。** 冷门曲目、未发行版本、tag 错乱的曲目，可能真的没有词。
  现在的行为是老实显示「未找到」，而不是硬凑一个错的。
