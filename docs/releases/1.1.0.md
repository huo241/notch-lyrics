# Notch Lyrics 1.1

1.0 gave this project its own identity. 1.1 fixes the reason 1.0 could not be
opened at all, and puts every string the app can show behind a translation
catalogue.

---

## 1.0.0 would not launch. This is that fix.

The 1.0.0 archive was built with the hardened runtime enabled and signed ad-hoc.
macOS's library validation requires that a loaded library and the process that
loads it share a Team ID — and an ad-hoc signature has no Team ID. The app embeds
a third-party framework for media control, so at startup `dyld` refused to load
it and the process died before drawing a window.

The hardened runtime stays on. What changed is a single entitlement,
`com.apple.security.cs.disable-library-validation`, which tells the loader to
skip that particular check for this app. Verified by launching the fixed build
and leaving it running: no crash.

This is why 1.0.0 is no longer in the update feed. Anyone who downloaded it has
an app that cannot be opened, so it can never reach the updater; there was
nothing to migrate them from.

## The interface no longer speaks a language you did not choose

A surprising amount of user-visible text was never in a translation catalogue at
all — it was Chinese string literals sitting in Swift source. Weather
descriptions (`晴`, `局部多云`), the lyrics pane's placeholders (`纯音乐`,
`加载中…`), the notes and Obsidian error messages — all of them hard-coded, so
every user saw Chinese regardless of their system language.

All 405 strings now live in `NotchLyrics/Localizable.xcstrings`, keyed by their
English source text. There are no Chinese keys; the source language is `en`.

**Translation status, stated honestly:**

| Language | Catalogue |
| --- | --- |
| Spanish, Simplified Chinese | complete — 399 of 405 strings; the other six are temperature glyphs and the app's own name, which need no translation |
| Arabic, Czech, German, English (UK), French, Hungarian, Italian, Korean, Polish, Portuguese (Brazil), Russian, Turkish, Ukrainian | 44% of 405 strings |

Languages in the second group fall back to English for everything they do not
cover, which is why they are worth including at all. Spanish and Simplified
Chinese were treated as the two targets that had to be finished.

The app's own name is in every AppKit-supplied dialog too: the permission
prompts macOS shows for Notes, Apple Events and the folder picker are translated
through a second catalogue, `InfoPlist.xcstrings`.

## Choose your language without leaving the app

The first row of **Settings › General** is now a language picker with 17 entries.
Each is labelled in its own language — `Español`, `简体中文`, `한국어`, `العربية`
— so the list stays readable when the interface is in a language you cannot read.

Two details worth knowing:

- **Changing it asks you to restart, and the restart is not optional.** macOS
  decides which `.lproj` a bundle resolves at process start. There is no way to
  re-point `Bundle.main` afterwards.
- **It writes one key in the app's own preference domain.** "Follow System" —
  the default — removes that key rather than writing a value, so a system
  language change is picked up again. Your system-wide language is never touched.

## The settings window was rebuilt on one set of components

All twelve pages — General, Appearance, Media, Calendar, HUD, Battery, Shelf,
QuickNote, Weather, Shortcuts, Advanced, About — now share a single component
library: one row, one section, one switch, one picker, one slider. Before this
they had drifted apart page by page, and it showed.

## Share what is playing

A share button in the open notch sends the current track to the system share
sheet: a text summary, the album art, and — where the player exposes one — a
link to the song. Spotify resolves an exact track URL; Apple Music falls back to
a search URL built from the track metadata, because MusicKit's
`SystemMusicPlayer` is not available on macOS. Other players get text and
artwork, and the share degrades instead of erroring.

## Known limitations

- **This build is not signed with an Apple Developer certificate.** It is
  ad-hoc signed and verified by Sparkle's EdDSA signature instead. On first
  launch macOS refuses to open it until you right-click the app and choose
  *Open*. A clean install without that step needs a paid developer account.
- **Drag the app to `/Applications` before running it.** Launching it from the
  Downloads folder triggers App Translocation: macOS runs it from a random
  read-only path, and both automatic updates and launch-at-login stop working.
- **Automatic updates need to reach GitHub.** The update feed and the release
  archives are both served from `github.com`; a network that cannot reach it
  gets no update and — because Sparkle fails silently by design — no error
  either. If you are behind such a network, check the Releases page by hand.
- **Lyrics depend on LRCLIB's coverage.** Obscure, unreleased or badly-tagged
  tracks may genuinely have no lyrics to find; the lookup says so rather than
  showing a wrong match.
