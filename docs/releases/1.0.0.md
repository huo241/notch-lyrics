# Notch Lyrics 1.0

**Not a patch release.** Everything up to now was upstream's app wearing a new
name. This is the first release where Notch Lyrics owns its identity, its lyric
pipeline, its update channel and its own idea of what the notch should do.

If you used boring.notch on macOS, you will recognise the notch. Almost nothing
underneath it is the same.

---

## The fork stops being a fork

Upstream's name is gone from every surface a user or a contributor can touch:

| Before | After |
| --- | --- |
| `boringNotch` project, target and scheme | `NotchLyrics` |
| Bundle ID `theboringteam.boringnotch` | `blog.snappy.notchlyrics` |
| `BoringNotchXPCHelper` | `NotchLyricsXPCHelper` |
| Upstream's app icon | A new one — a seam of warm light leaking out of a dark notch |
| CI badges, workflow names, funding links | This repository's own |
| A release job that published to upstream's Homebrew tap | Deleted — this fork does not publish to anyone else's tap |

The GPL requires that a modified version says so, and it does: `NOTICE`, the
modification notices dated 2026-10-06 at the top of each README, and a line in
the About panel.

## Lyrics: rebuilt from the query up

The old lookup asked LRCLIB one question and gave up if the answer was no. Most
missing lyrics were never missing at all — the request was simply wrong. Three
changes fixed that.

**1. Stop demanding a perfect duration match.** LRCLIB's exact-match endpoint
tolerates a duration mismatch of *two seconds*. A track whose reported length is
three seconds off — a re-release, a fade-out, a slightly different master — was
invisible. The lookup now walks down a ladder: exact match with duration, then
the same query without it, then a search whose results are ranked locally.

**2. Strip the noise from the title.** Candidates are derived from what the
player actually reports, in order: the spelling as given, then with bracketed
qualifiers removed, then with a dash-suffix (`- Remastered 2011`) removed, then
with only the first credited artist. The original spelling is always tried
first, so a clean track is unaffected.

**3. Score before you trust.** Search results are compared against the track
that is playing — title, artist and duration, weighted — and anything that
scores below a threshold is rejected rather than shown. Matching the wrong song
is worse than showing nothing.

Along the way a real bug: the query encoder was using `urlQueryAllowed`, which
does **not** escape `&`, `=` or `+`. Any title containing an ampersand truncated
the request at that character.

**The active line now fills as the song plays.** No bouncing ball, no
per-syllable highlight — the current line wipes from dim to bright over its own
duration, measured against the width of the text itself rather than the panel,
so short lines fill on screen exactly as fast as long ones.

*Not shipped: word-by-word karaoke.* LRCLIB's format supports it, and the
endpoint returns the field, so the work was done — but a sweep of roughly 973
real records found **zero** carrying genuine word-level timings. A feature that
can never light up is not worth shipping.

## Quick notes: Notes or Obsidian

The quick-note panel now asks where a note should go — Apple Notes, as before,
or a folder in an Obsidian vault. Choosing a vault is a one-time system dialog;
the grant is stored as a security-scoped bookmark and no new entitlement is
requested. Notes folder listing is only performed when Notes is the active
target, so the Apple Events round trip stays off the hot path.

## The update channel is this project's own

Sparkle used to check upstream's feed with upstream's key. It now checks this
repository's feed with a key generated for this fork, and `scripts/release.sh`
builds, packages, signs and files a release in one step.

## YouTube Music reports its own name

The YouTube Music desktop client it talks to keeps a per-client permission
list, and this fork was announcing itself as upstream. It now introduces itself
as `notchLyrics`, which means the desktop app will ask once, again, before
allowing it.

## Fixed

- The lyrics switch was labelled *"Show lyrics below artist name"* — a location
  that has not existed for a long time. Lyrics have their own pane on the right
  side of the open notch, sharing the space with the calendar and the camera.
  It now reads **"Show lyrics in the notch"**, and the simplified-Chinese
  catalogue has an actual translation (`在刘海显示歌词`) instead of falling
  back to English.

## Known limitations

- **This build is not signed with an Apple Developer certificate.** It is
  ad-hoc signed and verified by Sparkle's EdDSA signature instead. On first
  launch macOS will refuse to open it until you right-click the app and choose
  *Open*, and again confirm the dialog. A clean install without that dance
  requires a paid developer account.
- **Automatic updates only go live once `updater/appcast.xml` is on `main` and
  a release archive is published alongside it.** Until then the feed is empty
  on purpose, so nobody is offered a download that does not exist.
- **Lyrics depend on LRCLIB's coverage.** Obscure, unreleased or
  badly-tagged tracks may genuinely have no lyrics to find; the lookup now says
  so rather than showing a wrong match.
